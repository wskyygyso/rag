# 证据：无完整问题模板的通用检索重构

- 日期：2026-11-06
- 阶段：18
- 目标：消除“回答失败后不断增加完整业务映射”的增长模式
- 状态：代码和真实仓库回归完成，等待用户审阅，尚未提交

## 1. 重构前问题

旧实现存在两类耦合：

1. 问题解析层保存项目专属的完整检索词和实现符号；
2. 回答失败后继续添加领域词条或固定链路，导致每遇到一个新问法就扩大映射表。

这会让召回看似增强，实际形成不可复用、难维护的项目特例集合；同时泛化词仍可能扩散出大量无关证据。

## 2. 本次实现

- 概念层只保留可组合业务词和代码词；
- 首轮只从问题原句提取中文业务片段、显式符号和通用概念；
- 增加检索支撑门禁，弱相关组合直接停止扩展；
- 动态从当前项目索引发现符号和配置键；
- 配置键增加定义值反查，例如完整键调用点回到真实配置字段；
- 调用链按入口分层保留，优先保留最近业务校验及扣款/转账方法；
- 最终证据固定上限 64，通用、配置、调用链和精确命中分层预算；
- 无支撑时证据、确定性事实和 LLM 调用均为 0。

## 4. 关键结果

### 钻石提现

任务 `diag_a32c29ef2157414488b22b4da9e7422b` 输出 4 条确定性事实：

- 当前仓库可执行入口为 `AdvanceServices::anchorWithdraw()`；
- 非土耳其代理提现最低约 400,000 钻石；
- 土耳其特殊比例下最低约 600,000 钻石；
- 提现成金币最低约 400 钻石；
- 当前扣款和转账链路没有独立平台手续费参数，不能据此断言线下渠道无费用。

配置定义反查词为 `diamond_to_usd`、`diamond_to_usd_tr`、`coin_price`、`min_money`。结果不再引用当前仓库不存在的 `WithdrawalOrderCreateService`。
